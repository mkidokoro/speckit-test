# 集合住宅向けインターホン住戸内モニター Constitution

## コア原則

### I. 組込み制約を満たす設計
組込みLinuxプラットフォーム上の制限を満たす必須原則。メモリ使用量は初期化時100MB未満、実行時150MB以下に制限。CPU使用率は待機時5%以下、通常動作時30%以下。ストレージは512MB以下。ブート時間は30秒以内。全機能は明記された制約内で動作することが必須。

### II. ハードウェア分離アーキテクチャ
通信層、UI層、ビジネスロジック層を明確に分離。各層は独立してテスト可能かつ交換可能であること。ハードウェアドライバーはLSB準拠の安定化インターフェース経由でアクセス。デバイスツリーと機能設定は中央集約。

### III. 信頼性最優先 (非交渉)
テスト駆動開発が必須。全新規機能はユニットテスト・統合テスト・デバイステスト完備後にリリース。故障時の自動回復機構を実装。クリティカルシステムコンポーネント（通信、認証）の冗長性設計は非交渉。

### IV. セキュリティ・プライバシー保護
映像・音声データは転送時・保存時ともAES-256で暗号化。認証は強力な暗号化パスワードハッシュ（bcrypt/scrypt）。API通信はTLS 1.3以上。デバイス識別情報と住戸情報は暗号化。セキュリティアップデート対応時間は30日以内。

### V. 低消費電力・スケーラビリティ
待機時消費電力は2W以下。ネットワーク通信はバッチ化・圧縮・キャッシング。スケーラビリティ想定: 数千デバイス同時接続時のシステム負荷は線形増加。アーキテクチャは予測された負荷パターンに対応可能であること。

## リソース制約基準

**メモリ管理**
- 初期化時: 100MB未満
- 実行時: 150MB以下（最大ビデオデコード時含む）
- メモリリーク検査: 全機能について7日間連続稼働テスト実施
- ガベージコレクション/メモリ解放: 明示的に実装・検証

**CPU使用率**
- 待機時: 5%以下
- 通常動作（ビデオ受信・UI表示・キープアライブ）: 30%以下
- 最大負荷（ビデオ受信+通話+UI操作同時）: 70%以下

**ストレージ**
- 合計容量: 512MB以下
- ログ保存期間: 30日間
- キャッシュ領域: 50MB以下

**ブート・シャットダウン**
- ブート時間: 30秒以内（初期化から完全稼働まで）
- グレースフルシャットダウン: 5秒以内

## セキュリティ要件

**認証・アクセス制御**
- デバイスペアリング: 対称鍵暗号またはPKI対応
- ローカル管理者認証: bcrypt/scrypt ハッシュ（workfactor ≥12）
- セッション管理: タイムアウト15分、トークン定期更新

**データ保護**
- 映像・音声: AES-256 GCM暗号化（転送時・保存時）
- API通信: TLS 1.3以上、正当な証明書署名
- パスワード・秘密鍵: メモリ内暗号化、不使用時解放

**ネットワークセキュリティ**
- ファイアウォール: デフォルト拒否、明示的許可リスト
- 監視カメラ映像: プロトコル署名・完全性確認
- DoS対策: レート制限、タイムアウト設定

**監査・コンプライアンス**
- セキュリティイベント記録: 暗号署名・タイムスタンプ付き
- アクセスログ: 全認証試行・ユーザー操作を記録
- 定期脆弱性診断: 開発周期ごと最低年2回

## 品質基準

**テスト**
- ユニットテスト: 新規コード70%以上カバー
- 統合テスト: 全通信プロトコル・ハードウェアインターフェース検証
- デバイステスト: 実機上での7日間連続稼働検証
- セキュリティテスト: ペネトレーション・ファジング実施

**ロギング・可視化**
- 構造化ログ: JSON形式、タイムスタンプ・レベル・コンポーネント付き
- 本番環境: 調査可能なERROR/WARN/INFOログのみ保存
- 開発環境: DEBUG/TRACEログは開発用ビルドのみ有効

**パフォーマンス**
- ビデオデコード・フレームレート: 仕様値以上の安定性
- UI応答性: ユーザー操作から500ms以内に視覚的応答
- ネットワーク遅延許容: 500ms以内での通信復帰

**信頼性**
- 平均故障間隔 (MTBF): 1年以上を目標
- 自動復帰率: クリティカルエラーの95%以上が自動復帰
- 定期再起動: 月1回以上のメンテナンスウィンドウ許容

## 開発フロー

1. 仕様書作成: 優先度付きユーザーシナリオ（P1/P2/P3）、受け入れ基準含む
2. テスト設計: ユーザーシナリオごとにテストケース設計・承認
3. テスト実装: 赤→緑→リファクタリング（全テストが失敗状態で開始）
4. 実装: テスト成功確認後に機能実装
5. デバイス検証: 実機上での統合テスト、リソース検証
6. セキュリティレビュー: コード・通信・データ保護レビュー実施
7. 本番リリース: 全チェック通過後、段階的ロールアウト
